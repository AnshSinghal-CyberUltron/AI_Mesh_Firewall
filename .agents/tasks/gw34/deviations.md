# GW34 deviations from design.md

Each entry: what design.md said, what was built, why. All are also recorded in the `## Deviations`
section at the end of `.kiro/specs/gw34-sdk-compat/design.md`.

| # | design.md said | Built | Why |
|---|---|---|---|
| V1 | One fold pair (and one detector call) per string leaf; tool/schema text as per-string redactable slots on `tool_description` / `tool_schema_text` / `response_format_schema` and per-string scan-only pairs on `tool_name` / `tool_call_id` / `tool_schema_struct` / `tool_arguments_raw`. | **Joined runs.** Every string of one tool channel in the whole request is joined with `JOIN_SEPARATOR` into ONE fold pair (`Builder.scan_only` / `Builder.joined_slot`, `openai_template.py`). A forwarded joined pair is split back on the separator after the input decision is applied (`TextSlot(index=JOINED, channel, part)`, `UpstreamTemplate.joined` / `pair_parts`); a changed part count, a non-JSON arguments part or an object-key collision is `input_unmaskable`. A request costs <= 8 detector calls however many tools it declares. | The measured detector cost is ~80 us p50 / 152 us p99 per call (`docs/plans/evidence/2026-11-04-gw34/scan-cost.json`), 7x the design's 20 us assumption; per-string folding needs ~228 calls for the 20-tool request against a 50-call cap. design.md names "widening subtree joining" as the permitted mitigation. |
| V2 | Join separator unspecified (the design mentions the ASCII record separator in my notes only). | `JOIN_SEPARATOR = "\ue000"` (private use). | ASCII `\x1c`-`\x1f` match `\s`; two adjacent UUIDs joined with `\x1e` became a phone-number false positive in the dev detector. A request string containing the separator is refused `malformed_wrong_shape`. |
| V3 | `_SCAN_SLOT_COST_US = 20` initially; the benchmark can only raise it. | `_SCAN_SLOT_COST_US = 200` (measured p99 152.1 us, rounded up with margin) so `max_scanned_slots = 50` at the 20 ms reference. | Measurement, as the design instructs. 20-tool request uses 8/50 (16%, required <= 70%); 40-tool uses 8/50 (stretch <= 80% met). |
| V4 | `ToolBounds.max_withheld_bytes = stream_buffer_bytes(active_streams())`. | `stream_buffer_bytes(connection_budget())`. | The contract has no `active_streams()`; `connection_budget()` is the largest stream count a worker admits, so the bound is the smallest per-stream share (conservative). The live per-stream ceiling is additionally enforced by charging the request's own `Coalescer`. |
| V5 | Call indexes forwarded as received. | The assembler **re-numbers output call indexes dense and ascending in first-emission order** (`_Call.out_index`). | The stock SDK's `accumulate_delta` merges `tool_calls` by list POSITION, not by `index`: an upstream that introduces index 2 before 0 (or interleaves) corrupts a call (found by Property 1 against the real SDK function). |
| V6 | Reserved delta keys include `role`. | `role` is NOT malformed; the decoder passes it and `_drain` drops it as today. Reserved (malformed): `finish_reason`, any key containing `#`, any key starting `output_tool_`. | Real providers send `delta.role = "assistant"` on the first chunk. |
| V7 | BLOCK-only attribution: any non-ALLOW decision on an overlapping finding is `input_blocked`. | REDACT and BLOCK escalate to BLOCK; **FLAG (monitor mode) stays FLAG**. | Escalating FLAG would make monitor-mode rules enforce on names and ids. |
| V8 | `StreamResponse` holds a role frame and a finish frame in two named slots while pending. | Nothing is held: the encoder puts `delta.role` on the first chunk it writes, and an empty / role-only / meta-only upstream frame never becomes an encoder chunk, so nothing is written (or buffered) until the first content-bearing event. | Same externally visible behavior (R7), no buffer to bound. |
| V9 | Counters `tool_calls_released` / `tool_calls_withheld` exported through the `OutcomeObserver` / Publisher, seeded zero. | `RequestHolds.note_tool_calls`; the counts are written to the audit `detail` as digit strings. **No new Publisher series.** | New Publisher series change the pinned `SERIES_COUNT` (R15 / P2) and its exposition tests; recorded as follow-up. |
| V10 | Python SDK non-stream and error cells use `httpx.ASGITransport`. | All Python SDK cells use the loopback uvicorn server. | The sync `httpx.Client` cannot use `ASGITransport` (`handle_request` missing); a real socket is the stronger proof anyway. |
| V11 | (not in design) | `x-request-id` is now sent on the 200 SSE start (`StreamResponse(request_id=)`, `start_sse(send, request_id)`). | The matrix asserts "x-request-id on every response"; the SDK exposes it as `response.request_id`. |
| V12 | (not in design) | `SSEEncoder.content(frame)` now emits ONE merged `choices[0].delta` per frame (was one choice per delta). | R5 (one merged delta); the SDK reads one choice. Three shipped codec property tests were updated to merge same-channel text. |
| V13 | R1.6 / matrix assertion: `amf.trace` never surfaces as a chunk. | **RESOLVED (owner decision, 4 Nov 2026).** The trace is now an SSE COMMENT line, `: amf.trace {compact json}\n\n` (`SSEEncoder.trace`), same payload and position, so the Python and Node SDK iterators never see it. `SSEDecoder.trace` exposes it; the Responses translator, frontend `consumeSSEStream` and all tests read the new framing. Node cell `c` is a normal passing test; both matrices assert R1.6. | Before: Python yielded a bare `ChatCompletionChunk` (no `choices`) and Node's `chat.completions.stream()` threw "chunk.choices is not iterable". Owner chose the comment framing over an in-band `choices: []` chunk or amending R1.6. |
