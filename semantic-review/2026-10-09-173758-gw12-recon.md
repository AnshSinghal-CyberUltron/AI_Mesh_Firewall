# GW12 reconnaissance — SSE egress / serving pipeline

Scope: survey the current state of the SSE egress and serving pipeline in `gateway_v2/` against card **GW12 — "Build the SSE egress pipeline with bounded buffers, backpressure and real cancellation."** No code was written or modified. All claims are cited to `file:line`/symbol.

## Executive summary

The streaming **holdback** half of the problem (the prior card **GW12b / R2-06**) is fully shipped and lives under `egress/` and `detect/`: a pure bounded-holdback scanner (`detect/holdback.py`), a window bound (`detect/windowing.py`), the owner-signed config (`runtime/holdback_config.py`), the label-free metrics producer (`runtime/holdback_metrics.py`), and a thin injectable release-loop harness (`egress/stream.py::StreamPipeline`) with its force-release trade-off mirror (`egress/holdback_tradeoff.py`) and output-decision glue (`egress/output_guard.py`). All five of C25's byte-linearity and the C4 split-latency / C24 kill primitives are present *inside the holdback harness*.

Everything that makes this an actual **serving pipeline** is still a stub. `edge/app.py` is `app = None` ("empty until GW12"); every route handler in `edge/` is an empty module; `edge/wire/` (the SSE codec + OpenAI types) is empty; `edge/errors.py` (the error envelope) is empty; `egress/backpressure.py` is empty ("until GW13" — note the comment is wrong, backpressure is GW12 per the card); and the entire `dispatch/` layer (`provider.py`, `routing.py`, `transform.py`) is stubbed "empty until GW12." So the SSE state machine, the bounded coalescer, credit-based flow control, real client-disconnect cancellation of the provider request, the fallback-splice guard, and the per-request export counters do **not** exist yet. The `ProviderClient` the cancellation path must abort is itself a GW12 deliverable that nothing has built.

`ResourceContract` already exposes the one derivation GW12 most needs — `stream_buffer_bytes(active_streams)` (`runtime/resources.py:135`) — but has **no** inter-chunk / idle / write timeout and **no** max-stream-duration derivation; those are the ResourceContract additions GW12 must make.

**Watch for:** the `egress → detect` layer edge is forbidden (import-linter `layers`, `pyproject.toml:68`), so GW12's SSE/dispatch wiring must keep injecting the detect scanner into `StreamPipeline` exactly as the harness already does — do not "simplify" by importing `detect` from `egress`. Also: `egress/backpressure.py`'s docstring says "empty until GW13," but the card assigns backpressure/credit flow control to **GW12**; treat the comment as stale, not as a scope signal.

**Verdict**: NEEDS_CHANGES — GW12's implementation work is almost entirely unbuilt (the expected finding for a spec-scoping recon; GW12b holdback is the only shipped half).

## High-level view

The holdback engine is a finished, self-contained subsystem. `detect/holdback.py::scan` is a pure function (seeded-property-tested) that decides how many trailing bytes of a text stream to hold vs. release, bounded by an owner-signed token cap (`runtime/holdback_config.py`, default 3) and a window (`detect/windowing.py::max_pattern_length` = 64 bytes). `egress/stream.py::StreamPipeline.run` is the async release loop that drives it over an injected chunk source and injected send sink, applies the output `Decision`, and emits `DownstreamFrame`s with terminal error codes. This is GW12b and it is done.

The serving skin around it is absent. There is no ASGI app, no router, no `/metrics` or `/readyz`, no lifespan, no SSE codec, no error-envelope builder, and no provider client — all of these are stub modules carrying "empty until GW12" docstrings. The `StreamPipeline`'s `DownstreamFrame` is an internal value type (`text_deltas` tuples + an `error_code`); nothing turns it into `data: {...}\n\n` wire bytes, a terminal `data: [DONE]`, or an SDK-shaped error frame.

The coalescer / backpressure / credit layer is empty (`egress/backpressure.py`), so there is no high-water mark, no slow-consumer flow control, and no `active_streams × ceiling` memory bound wired up — even though the exact derivation (`ResourceContract.stream_buffer_bytes`) already exists and is unit-represented in `snapshot()`.

Real cancellation does not exist end to end. The holdback harness has an in-flight **kill** probe (`killed()` checked at each chunk boundary, `egress/stream.py` `_run_enforcing`), which satisfies the C24 kill-switch cut semantics *for the holdback loop*, but there is no client-disconnect detector, no provider-request abort (the provider client is a stub), and no bounded+measured guard-cancel interval.

The house conventions GW12's spec must honor are all evidenced in the shipped R2 cards and the GW12b code: frozen-slotted dataclasses, `StrEnum`, no module-level mutables (`MappingProxyType`), no capacity literals outside `runtime/resources.py` (AST-gated), producer-only label-free metrics, and the "egress/admit return values, edge renders HTTP" codes-vs-render boundary (`domain/posture.py`).

## A. The 7 GW12 requirement groups, point by point

### 1. One SSE state machine (SDK-parseable frames, terminal DONE, error-frame shape) — ABSENT

There is no SSE state machine. `edge/wire/__init__.py` is empty ("OpenAI request/response types and SSE codec — empty until GW01/GW12"). A grep for `data: [DONE]`, `text/event-stream`, or `StreamingResponse` across the whole `gateway_v2/gateway_v2` package returns nothing (the only `asyncio.CancelledError` hits are in `runtime/state_nudge.py`, `runtime/storemem.py`, `audit/sink.py` — unrelated store code).

What exists is one layer down and internal: `egress/stream.py::DownstreamFrame` (a frozen-slotted value with `text_deltas: tuple[tuple[str, str], ...]` and an optional `error_code`). Its docstring enumerates the terminal codes the harness already produces — `forced_release_tradeoff`, `holdback_overflow`, `undefined_tradeoff`, `scan_failure`, `output_blocked`, `killed`. GW12 must build the thing that serializes a `DownstreamFrame` into `data: {json}\n\n` chunks the OpenAI SDKs parse, emits the terminal `data: [DONE]`, and renders a declared error frame from `error_code`. None of that exists.

### 2. One bounded coalescer, high-water from ResourceContract, never grows — ABSENT (derivation present)

`egress/backpressure.py` is empty. There is no coalescer class. The *derivation* GW12 needs is already shipped: `ResourceContract.stream_buffer_bytes(active_streams)` (`runtime/resources.py:135`) returns `floor(memory_limit * utilization_cap / streams)` and raises `CapacityUnavailable` below 1 — exactly the `f(active stream count, memory limit)` the card asks for, with no literal. `snapshot()` already exercises it at `active_streams=1` (`runtime/resources.py:289`). So the no-literal high-water source exists; the coalescer that consumes it and applies backpressure does not.

### 3. Credit-based flow control, memory = active_streams × ceiling, derived+exported — ABSENT (derivation present)

No credit primitive anywhere (`egress/backpressure.py` empty). The per-stream ceiling is `stream_buffer_bytes`; the `active_streams × ceiling` product is derivable from it but is not computed, bounded, or exported anywhere. GW12 builds this.

### 4. Real cancellation (client disconnect → provider abort + guard-cancel, bounded+measured) — PARTIAL (kill primitive only)

The holdback harness has an in-flight **kill** mechanism: `StreamPipeline._run_enforcing` calls `killed()` at each chunk boundary and, on a kill, routes to `_cut_on_kill`, discarding still-held bytes and emitting a `killed` terminal frame (`egress/stream.py`, `InFlightKill.CUT_NEXT_CHUNK`, `domain/locks.py:22`). That is the C24 kill-switch cut *for the release loop*.

What is ABSENT: a client-disconnect detector (no ASGI receive loop exists), a provider-request abort (the provider client is a stub — see F), and a bounded, MEASURED guard-cancel interval. The `killed()` probe is a `Callable[[], bool]` injected by the caller; nobody wires it to a disconnect or a kill-switch snapshot yet.

### 5. Never splice a fallback into a stream that already emitted content — ABSENT

No first-byte latch, no retry/fallback logic in `egress/` or `dispatch/`. `dispatch/routing.py` ("Deterministic selection from the plan — empty until GW12") and `dispatch/provider.py` are stubs, so there is no place where a signed pre-first-byte retry could run and no guard preventing a post-first-byte splice. GW12 builds the latch and the "before first byte → signed retry; after → clean termination or declared error frame" rule.

### 6. Export per-request: output-detector invocation count, release lag, buffer high-water — ABSENT / PARTIAL

`runtime/holdback_metrics.py::HoldbackMetrics` is a fleet-level, label-free producer. It exports held-tokens histogram, two separate latency histograms (`release_processing_ms`, `holdback_wait_ms`), `unbroken_run_bytes_max`, and `incomplete/overflow/forced_release` counters. It does **not** export a per-request output-detector invocation count, a per-request release-lag, or a buffer high-water — the card asks for per-request export, and the detector invocation count in particular has no counter at all (the detector is an injected `Detector` callable in `egress/stream.py` with no instrumentation around it). GW12 adds the per-request export surface.

### 7. v2.1 / C-corrections — MIXED

- **C4** (split `T_release_processing` [in SLO] vs `T_holdback_wait` [published separately]) — DONE. `egress/stream.py::StreamStats` carries `release_processing_ns` and `holdback_wait_ns` as two separate fields; `runtime/holdback_metrics.py` records them into two separate histograms with the documented R5.3 split.
- **C25** (scanning linear in bytes, bounded held-byte ceiling, O(1) per byte released) — DONE for holdback. `detect/windowing.py::window_slice` bounds the inspected span to the trailing `window` (64) bytes; `detect/holdback.py::scan` is pure and O(window); the token cap + `2*cap` relaxed ceiling (`runtime/holdback_config.py`, `detect/holdback.py::scan` overflow path) bound the held bytes. The seeded ≥10k-iteration byte-invariant properties live in `tests/detect/test_lgw12b_holdback.py`.
- **C24** (max stream duration + signed in-flight semantics for kill / key-revocation / plan-change) — PARTIAL. The kill-switch cut semantics exist (`InFlightKill.CUT_NEXT_CHUNK`, the `killed()` probe). There is NO max-stream-duration anywhere, and NO key-revocation / plan-change-mid-stream handling. `domain/posture.py:KILL_SWITCH_UNAVAILABLE` is the vocabulary but no producer uses it in egress.
- **C27** (bounded inter-chunk / idle / write timeouts) — ABSENT. No timeout exists in `egress/` and `ResourceContract` has no timeout derivation (see E).
- **C38** (stream loops run no CPU slice too long; tokenization/scanning in GIL-releasing executors; metrics exposition off the serving loop; loop lag an SLO input) — PARTIAL / structural only. The holdback compute is O(window) and single-threaded (asserted structurally by `tests/egress/test_lgw12b_concurrency.py`), and `HoldbackMetrics.snapshot` computes percentiles on read (off the hot path). But there is no executor offload, no serving loop (it doesn't exist yet), and no loop-lag SLO input. GW12 owns the executor-offload + loop-lag parts once the serving loop exists.
- **Scan provider mid-stream error frames** — ABSENT (no provider read loop exists).
- **Tolerate split UTF-16 surrogate escapes** — ABSENT (no SSE decoder exists).
