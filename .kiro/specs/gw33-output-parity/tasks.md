# Implementation Plan: gw33-output-parity

Implementation order, bottom-up along the layer contract: domain, then contracts, then runtime, then audit, then egress, then dispatch, then resolve, then detect, then plan, then admit, then edge, then the control plane (the import-linter contract is written top-down, `edge > admit > plan > detect > resolve > dispatch > egress > audit > runtime > contracts > domain`; a higher layer may import a lower one, never the reverse). Each task names the files it touches and the tests that close it. Property tests are seeded `random.Random`, at least 100 iterations (10,000 where cheap), tagged `# Feature: gw33-output-parity, Property N: <name>` with a docstring naming the requirement. Do not run live gates. Status wording everywhere: "local half closed; live L33-1..L33-3 deferred".

All paths are under `gateway_v2/gateway_v2/` unless they start with `control/`, `lint/` or `tests/`.
