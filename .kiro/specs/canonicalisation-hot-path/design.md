# Task 1F — design

## Change 1 — an ASCII identity fast path, derived not rewritten

Factor the existing per-character body into `_canon_char(ch)` returning the replacement
or `None` for "drop". Then, at import, run it over all 128 ASCII code points and keep
those that map to themselves:

```python
_ASCII_IDENTITY = frozenset(c for c in map(chr, range(128)) if _canon_char(c) == c)
```

Because the table is *generated by the existing logic*, it cannot disagree with it (R1).
If someone later edits the per-character rules, the table changes with them.

Fast path: if every character of the input is in `_ASCII_IDENTITY`, the canonical form is
the input and the index map is `list(range(n))` — no Python-level loop, no
`unicodedata` calls at all. Otherwise fall through to the existing loop unchanged.

The membership test is a single C-level `str.translate`-based check rather than a Python
`all(...)` generator, so the fast path does not pay per-character Python overhead either.

## Change 2 — collapse the 3× repeat

`functools.lru_cache(maxsize=32)` on `canonicalize_for_detection`. Strings are immutable
and hashable, so memoisation is sound; maxsize bounds memory (R5). Within one scan the
three calls become one plus two hits.

`_canonicalize_with_map` itself is NOT cached — it returns a mutable list, and handing
the same list to two callers would be a sharing hazard.
