## 6. GitHub Enterprise: what to use
From github.com/pricing (12 Nov):
- 50,000 Actions minutes per month;
- environment protection rules on private repos;
- rulesets;
- required reviewers;
- CODEOWNERS;
- audit log API;
- SAML SSO;
- Copilot access.

GitHub Secret Protection and Code Security are paid add-ons. Check `security_and_analysis` on the repo before relying on CodeQL, secret scanning or push protection in a private repo.

Proposed setup, to confirm with the owner and apply as an org or repo admin:
1. **Rulesets on `develop`, `staging` and `main`:**
   - required status checks, matching `.github/ci/required-checks.txt`;
   - linear history off;
   - no force push;
   - **merge queue** on `develop`, so parallel PRs re-test against the queue head.
2. **Environments `staging` and `production`** with required reviewers and deployment branch rules. Promotion PRs `develop`→`staging`→`main` deploy through them.
3. **Larger runners** for `structural-gates`, the full gateway suite and control. This also answers the local-suite bottleneck.
4. **Copilot code review** as an automatic extra reviewer on every PR (the owner asked for CodeRabbit-style bots). It is additive: it does not replace agents A and B.
5. **Actions policy:**
   - require actions pinned to a full-length SHA;
   - default `GITHUB_TOKEN` read-only;
   - turn on the dependency graph and Dependabot security updates.
6. **If the add-ons are purchased:** secret scanning with push protection, CodeQL default setup, and the dependency review gate as required.
7. **Mind the 1-owner-account limit:** reviews posted by agents through the owner's token cannot satisfy "required approving reviews" from a different user. Keep the COMMENT-review policy, or add a machine user or GitHub App for agent reviews.
