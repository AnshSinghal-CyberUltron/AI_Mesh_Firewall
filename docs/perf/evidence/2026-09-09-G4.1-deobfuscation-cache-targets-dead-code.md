# G4.1 (`lru_cache` on `_deobfuscate_text`) no longer applies — do not implement it

**Tag `[M]`** (reachability by grep on this tree) · `dev/perf-9stage`

## The plan's claim

`docs/plans/2026-08-27-task-tracker.md`, Gate 4:

> **G4.1** — `lru_cache` on `_deobfuscate_text` — **1,186.5 → 100.2 ms (11.8×), verdict
> byte-identical** `[M]`; 440 hits / 40 misses on ONE prompt, so the win is *intra*-request

It is listed as the largest zero-dependency win available. On this tree it is worth
approximately nothing, for two independent reasons.

## Reason 1 — one of the two call sites is dead

`_deobfuscate_text` has exactly two callers:

| line | enclosing function | status |
|---:|---|---|
| 1269 | `_scan_prompt_sync_disabled_builtin_default` | **dead** — grep finds no callers |
| 2103 | `async def scan_prompt_with_tier2` | live, but Tier-2 only |

The first is the retained-disabled reference copy of the former built-in Tier-1 scan.
`_scan_prompt_sync` now returns `ScanVerdict()` immediately (`scanner.py:1160`);
detection is sourced from policies at the enforcement seam. The 1,186.5 ms figure was
measured against that deleted scan.

## Reason 2 — the mechanism does not exist on the live path

The quoted win is **intra-request**: 440 cache hits against 40 misses within a single
prompt, because the old built-in scan called `_deobfuscate_text` once per pattern.

The surviving call site executes **once per `scan_prompt_with_tier2` call**, after the
Tier-1 early-return and the breaker checks. There is no repetition inside a request, so
there are no intra-request hits to harvest. A cache would add a lookup and a lock and
return the same work.

Cross-request hits would require two requests with identical prompt text — and the
tracker itself notes the win was intra-request precisely so the change carried **no
cross-tenant cache surface**. A cross-request cache would introduce one.

## What is still true

On the Tier-2-enabled path the call does real work, so it is not free. But:

- the contracted primary posture is `ENABLE_TIER2=false` (verified in the running perf
  container), where the line never executes;
- when Tier-2 *is* on, the cost is dominated by the guard-model round trip, not by
  deobfuscation;
- D18 removes Bedrock entirely, which is the reason that path exists.

## Recommendation

**Do not implement G4.1.** Mark it superseded, as G0.3 was when it turned out to target
`ATTACK_PATTERNS["command_injection"]` — also dead code. Two of Gate 4's items now aim at
code paths the `policy-driven-detection` work removed; the rest of the gate should be
re-checked for reachability before any of it is scheduled, rather than trusting the
`[M]` tags, which were measured against a tree where that scan still ran.

The equivalent win **was** available and has been taken elsewhere: task 1F cached
`canonicalize_for_detection`, which genuinely is called three times per output scan on
the live path, for a measured 1.4–1.7× (`…-1F-canonicalisation-fast-path.md`).
