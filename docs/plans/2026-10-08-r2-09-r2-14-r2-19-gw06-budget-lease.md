**Status:** implemented, local half CLOSED. **Card:** GW06 (v3 amendment).

**Evidence:** `docs/plans/evidence/2026-10-08-r2-09-gw06/`.

## 1. Executive summary

The org-level token budget was enforced with a **synchronous store read on the request path**: a
lease refill needed the store, and it was done on the hot path, so a store partition failed large
prompts almost immediately instead of after the declared RAM window. Round 2 measured three
distinct defects on the budget / quota / store-connection path:

- **R2-09 (HIGH) — refill on the request path.** Budget-lease refills ran on the request path, so a
  store outage failed large prompts from +0.15 s instead of after the declared 5 s RAM window.
  Measured on the RC2 fleet during a 45 s store partition: **211 × HTTP 503
  `shared_state_unavailable` from +0.15 s, inside the declared 5 s RAM window** — because a lease
  refill needs the store and was being issued synchronously on the hot path, and a budget-counter
  problem was reported as a global state outage.
- **R2-14 (MEDIUM) — no retry on the rare cross-zone RTO.** Roughly **1e-4 of cross-zone store round
  trips hit the 200 ms minimum TCP RTO**, over the 25 ms request-path timeout, so a transient
  cross-zone timeout failed a read that a single retry would have recovered.
- **R2-19 (HIGH, already fixed in the prototype) — store-connection boundary.** A redis-py keepalive
  `ETIMEDOUT` was read as "no message", so the push listener spun to out-of-memory (defect **D2**);
  a dead pooled socket answered 500 (defect **D1**). This card is a **port + regression-test** into
  `gateway_v2`, not a rewrite.

The fix makes the org budget a **shared lease spent locally** rather than a synchronous store read
on the hot path. A Low_Watermark Async_Refill keeps the lease topped up **off the request path**;
during a store outage identity / kill switch / plan stay RAM-served for the declared window while
budget spends the Remaining_Lease and then refuses **only quota** with the distinct narrow
`budget_unavailable` posture (never `shared_state_unavailable`); leases are generation-tagged and
revoked on budget-config change, TTL-reclaimed on worker crash, and **never multiplied** by worker
or replica count. An idempotent store read is retried **at most once** on timeout; the mutating
atomic acquire / return is **never** retried.

The component is built **bottom-up along the import-linter `layers` contract** (`admit` imports only
`runtime` + `domain`): the budget-lease + GCRA is NEW code added to the `admit/quota.py` module the
card reserves for it, next to the GW19 `derive_bounds`. Capacity-position literals come only from
the `ResourceContract` (`runtime/resources.py`); the Lease_Chunk is **derived from the contract**,
never a constant; the measured `q_safe`-style rate is **injected, never hardcoded**. The store
client, the clock (`Callable[[], float]`), and the refill task spawner are all **injected**, so the
whole state machine is locally reproducible under `asyncio.run` with `fakeredis` — no cloud fleet.

| # | Mechanism | Where |
|---|---|---|
| 1 | Budget-lease store key family under the `{rv2}` hash tag (one slot, cluster-safe) | `runtime/store_keys.py` |
| 2 | Pure `LocalGCRA` — burst + rate, per worker, injected clock, no store round trip | `admit/gcra.py` |
| 3 | Store-backed `BudgetLease` — atomic acquire, local `try_spend`, off-path refill, return/TTL-reclaim | `admit/lease.py` |

| 6 | Producer-only, label-free `QuotaMetrics` (overshoot / refill / budget_unavailable) | `admit/metrics.py` |
| 7 | R2-19 / R2-09 45 s partition regression (confirm the boundary, prove the budget posture) | `tests/runtime/test_lgw06_partition_regression.py` |

## 2. What was built

### 2.1 The store key family (`runtime/store_keys.py`)

`StoreKeys` gains `budget_remaining(org)`, `budget_generation(org)`, and
`budget_lease(org, worker_id)`, all under the existing `{rv2}` namespace hash tag so every op for
one org stays in one slot (cluster-safe) and the atomic acquire / return touches only keys in that
slot. The keys are the **live counter** family
(`{rv2}:budget:<org>:remaining` / `:generation` / `:lease:<worker_id>`), kept distinct from the
existing published `StateKind.BUDGET` config record.

### 2.2 The pure local GCRA (`admit/gcra.py`)

Frozen slotted `GcraParams(rate_per_s, burst)` and `LocalGCRA(params, *, clock)` carrying only a
small mutable TAT (theoretical arrival time) carrier. `admit() -> bool` returns `True` when the
arrival is within burst + rate at `clock()` now and advances the TAT **only on admit**. There is no
store round trip, ever — the decision is a pure function of the injected clock and the params, which
are supplied by the façade (no capacity literal in the module). GCRA governs **burst and rate**; the
lease governs the **org-level token budget**.

### 2.3 The store-backed lease (`admit/lease.py`)

Frozen slotted `LeaseConfig(org, chunk, low_watermark, ttl_s)`, the single mutable
`_LeaseState(remaining, generation, refill_in_flight)` carrier (not frozen; no module-level mutable
state), a `SpendResult` value, and a `QuotaMetricsLike` Protocol. `BudgetLease.__init__` takes the
injected store `client`, `config`, `worker_id`, injected `clock`, injected `spawn`, `keys`, and
`metrics`.

- **`async acquire(generation)`** is an **atomic compare-and-decrement** of the shared pool: a
  generation check (stale → re-read the generation and re-acquire under the current one),
  `grant = min(pool, chunk)` so it never over-grants, decrement of the shared remaining, and a
  per-worker `lease:<worker>` record with a TTL on the **store's clock**. It is implemented as a
  `WATCH`/`MULTI` optimistic transaction (**not** a Lua `EVAL` — `fakeredis` 2.39 lacks `EVAL`; real
  Valkey implements `WATCH`/`MULTI` identically, and the no-multiplication property proves the
  invariant holds either way), bounded by `_MAX_CAS_TRIES = 16` CAS attempts before it reports an
  empty grant.
- **`try_spend(cost, generation)`** is **synchronous and local** — no `await`, no store read. It
  decrements the Remaining_Lease; at or below the `low_watermark` it schedules an Async_Refill via
  the injected `spawn` and returns immediately; a stale generation is unspendable. A single-flight
  `refill_in_flight` guard ensures at most one refill is in flight, and a `try_spend` that fires the
  watermark during an in-flight refill schedules nothing new and keeps serving from the
  Remaining_Lease. `acquire` runs only at construction and from the refill task — **never** from
  `try_spend`.
- **`async return_unspent()`** atomically adds the unspent Remaining_Lease back to the pool and
  deletes the per-worker record on clean shutdown. A crashed worker never runs this; its
  `lease:<worker>` key **expires on the store's clock** so the budget is reclaimed, never lost.
- The idempotent read boundary retries at most once (`_IDEMPOTENT_READ_RETRIES = 1`) — see §2.6.

### 2.4 The verdict value (`admit/grant.py`)

Frozen slotted `BudgetVerdict` mirrors the existing `ShedVerdict` code-vs-render split:
`code = posture.BUDGET_UNAVAILABLE`, `retry_after_s` from `gap_retry_after_s`
(≥ `MIN_RETRY_AFTER_S`), `should_retry = False`, `request_id`. It constructs **no HTTP object** —
`edge` renders the 503 + `Retry-After` + `x-should-retry`. `BUDGET_UNAVAILABLE`, `MIN_RETRY_AFTER_S`,
and `gap_retry_after_s` are **reused** from `domain/posture.py`; no second budget-outage code is
defined.

### 2.5 The chunk derivation and the façade (`admit/quota.py`)

`derive_lease_chunk(contract, *, q_safe)` computes the Lease_Chunk from the `ResourceContract`
measured inputs; `derive_low_watermark(chunk)` is a function of the chunk only. Both are pure (no
store, no clock) and **refuse to start** (`CapacityUnset` / `CapacityUnavailable`) when uncomputable
or `q_safe` is unset / non-positive. The chunk formula:

```
raw   = ceil(q_safe * target_p99_ms / 1000)
chunk = min(raw, contract.queue_depth(q_safe))
watermark = min(floor(0.25 * chunk), chunk - 1)
```

No capacity literal lives in the module (the reused `admit/` capacity-literal AST gate covers the
new code); `derive_bounds` (GW19) is unchanged.

`QuotaComponent(gcra, lease, *, generation_source, metrics)` is the request-path entry point.
`evaluate(cost, request_id)` composes: (1) the local GCRA burst + rate check → refuse on over; (2)
the generation check → re-acquire under the current generation if stale; (3)
`lease.try_spend(cost, gen)` → `Admitted`, or `budget_unavailable` when the pool and Remaining_Lease
are both exhausted under outage. It performs **no store I/O**, owns the composition order
(GCRA-first, then budget) and the fail-closed catch-all (refuse on any undecidable decision), owns
**only** the narrow `budget_unavailable` posture, and **never** returns `shared_state_unavailable`.

### 2.6 The retry-once boundary (R2-14, `admit/lease.py`)

An idempotent store read that times out (per `bounded_timeout_s`) is retried **at most once**
(`_IDEMPOTENT_READ_RETRIES = 1`); a second timeout **surfaces** rather than retrying again. The
mutating atomic acquire / return is **never** retried on timeout. The module documents that gateway
placement in the store primary's zone is a **deployment dependency** and the retry-once-on-timeout
is the code-side requirement.

### 2.7 The metrics (`admit/metrics.py`, producer-only)

`QuotaMetrics` follows the existing `AdmissionMetrics` producer-vs-publisher split: three fixed,
**label-free** series seeded to zero at construction — `amf_quota_lease_overshoot` (the declared
aggregate overshoot), `amf_quota_async_refill_total`, `amf_quota_budget_unavailable_total`
(`QUOTA_PREFIX = "amf_quota"`, `QuotaReading` snapshot). No tenant-derived (owner / org) label on any
series; GW14d owns fleet publication. The producer is wired into `BudgetLease` (refill count) and
`QuotaComponent` (budget_unavailable count, overshoot).

### 2.8 The store-connection boundary — confirm + regression, not rewrite (R2-19 / R2-09)

Per the card, task 11 is **confirm + regression-test**. `runtime/state_nudge.py` **already contained
the D2 fix** (keepalive-`ETIMEDOUT`-not-silence; the three dead-connection signatures
`error` / `no_wait` / `silent`; `FAST_NONE_LIMIT = 3`; reconnect-after-backoff) and was **not
rewritten**. No D1 gap was found in `store_valkey.py` (the redis-py pool reconnects), so **no guard
was added**. The new 45 s partition regression (`tests/runtime/test_lgw06_partition_regression.py`,
Property 7) proves **D2** (the listener surfaces the keepalive timeout and does not spin to unbounded
memory), **D1** (a dead pooled read socket reconnects rather than answering 500), and **R2-09**
(budget spends the Remaining_Lease then returns `budget_unavailable`, never
`shared_state_unavailable`, with no store read on the request path to refill).

### The layer rule and the codes-vs-render boundary

`admit` **never constructs an HTTP object**: it returns a frozen `BudgetVerdict` (a code +
`retry_after_s` + `should_retry` + `request_id`) and `edge` renders the 503 — the same split
`posture.py` already enforces. `admit` imports only `runtime` (`ResourceContract`, the capacity
exceptions, `store_keys`, `store_valkey` helpers) and `domain` (`posture.*`), both below it, and
**never** a layer above. The store client, clock, and refill spawner are injected. The import-linter
`layers` and `forbidden` contracts verify this.

### 3.2 LGW06-3 (local) — multi-replica, no quota multiplication

N in-process `BudgetLease` replicas (each with its own `worker_id` and its own `LocalGCRA`) share
**one** `fakeredis` budget pool over a seeded arrival stream of ≥ 10,000 arrivals, driving the real
contract-derived chunk. Aggregate admission stays **≤ limit + overshoot** (the overshoot is at most
one in-flight chunk per worker), the overshoot is **published** and read back from the snapshot, and
the aggregate is **strictly below `limit × workers`** for `workers > 1` — the shared lease, not a
per-worker counter, is what stops Replica_Multiplication. Validates Req 11.1 / Property 1.

### 3.3 LGW06-5 (local) — injected 200 ms store latency

A 200 ms cross-zone RTO is modelled as a deterministic injected-clock advance (never a wall-clock
`sleep`). The harness asserts three things: (1) the **bounded-timeout contract bites** —
`require_bounded_client` accepts the lease's client (its `socket_timeout` is below the refresh
period) and the modelled 200 ms op is strictly greater than that per-op timeout; (2) the **declared
posture holds** — the façade admits while the Remaining_Lease has budget and returns
`budget_unavailable` once it is exhausted, the latency not changing the posture; (3) the **pool does
not grow unbounded** — the lease holds one client for its whole lifetime and the request path creates
**zero** connections (the request path advanced the simulated clock by zero, proving no store op
leaked onto it). Validates Req 11.2.

### 3.4 R2-09 (local) — partition spends Remaining_Lease then budget_unavailable

During a `fakeredis` partition the façade admits exactly the pre-acquired Remaining_Lease, then
refuses every subsequent request with `budget_unavailable` (never `shared_state_unavailable`,
`should_retry` `False`, `retry_after_s ≥ 1.0`), and a request-path store-call counter stays **0**
across the whole run — no synchronous refill read ever reaches the store on the hot path. This is the
harness-level tie-together of the Req-11 partition behaviour, mirroring the R2-09 baseline shape (the
211 × inside-window `shared_state_unavailable` failures) with the fixed behaviour. Validates Req 11.3
/ Properties 4, 5.

### 3.5 The 45 s partition regression (R2-19 / R2-09, Property 7)

`tests/runtime/test_lgw06_partition_regression.py` drives a 45 s simulated store partition
(`fakeredis` + an injected clock + a keepalive-`ETIMEDOUT` / dead-socket simulation) and asserts the
D2 listener surfaces the keepalive timeout and does not spin to unbounded memory, the D1 dead socket
reconnects rather than answering 500, and the R2-09 budget posture (spend Remaining_Lease →
`budget_unavailable`, no request-path refill read).

### 4.2 The R2-14 zone-placement deployment dependency

Placing the gateway in the store primary's zone (so a store round trip is never cross-zone) is a
**deployment dependency, not code**. The code-side requirement is the
retry-once-on-idempotent-read-timeout, which **is** implemented (`_IDEMPOTENT_READ_RETRIES = 1`,
§2.6) and tested (Property 6, `tests/admit/test_lgw06_retry_once.py`). The module documents the zone
placement as the deployment-side half (Req 8.4).

### 4.3 R2-19 — confirm + regression-test only (honest note)

R2-19 was **confirm + regression-test**, not a rewrite. `runtime/state_nudge.py` already contained
the D2 fix and the working `NudgeListener` was **left intact** (no rewrite). No D1 gap was found in
`store_valkey.py` (the redis-py pool reconnects), so **no guard was added**. The 45 s partition
regression (§3.5) is the new artifact; it proves D2, D1, and R2-09 all at once.

### 4.4 Found, not fixed / honest notes

- **Benign known warning.** The lease property tests emit
  `RuntimeWarning: coroutine 'BudgetLease._refill' was never awaited` for undrained single-flight
  refill coroutines (the tests exercise the single-flight guard without always draining the spawned
  task). This is **not a failure** — the full offline suite is 1131 passed / 0 failed.
- **The harness is an in-process injected-clock simulation**, not a wall-clock fleet; every number in
  §3 is computed under the fake clock, so the numbers are **deterministic** and not sensitive to CI
  wall-clock jitter — the same realism caveat the R2-06 / R2-07 harnesses carry.
- **`WATCH`/`MULTI` not `EVAL`.** `fakeredis` 2.39 lacks `EVAL`, so the atomic acquire / return uses
  an optimistic `WATCH`/`MULTI` transaction (bounded by `_MAX_CAS_TRIES = 16`). Real Valkey
  implements `WATCH`/`MULTI` identically; Property 1 (no multiplication) proves the invariant holds
  regardless of the atomic primitive.
- **Cross-component outage posture.** This card owns **only** the narrow `budget_unavailable` budget
  posture. Identity / kill switch / plan being RAM-served for the declared window during an outage is
  cross-referenced, not owned here (GW05); Property 4 asserts the budget posture is decoupled from
  them.
