1 · The finding that matters

The plan was about to recommend shipping Tier-1-only as the default posture and certifying 12 ms for it. Nobody had ever measured what Tier-1-only detects.

Measured against the real InputScanner._scan_prompt_sync at HEAD:

ProbeResultMeaning
Bare English prompt injections, same family as the shipped regexes3 / 10detected
The same injections paraphrased with disjoint trigger vocabulary0 / 10detected
Benign prompts containing inline-backtick code5 / 5hard-blocked, confidence 1.00
Ordinary agentic tool descriptions3 / 12hard-blocked, confidence 1.00
Root cause. ATTACK_PATTERNS["command_injection"] contains the literal pattern r"`[^`]+`" — any backtick pair. command_injection and data_leakage are excluded from the explanatory carve-out (scanner.py:104, tested at :1201), so the block is terminal at :1212-1219, tier_1, and never reaches Tier-2.

The recommended default posture is near-blind on the primary threat and hostile to ordinary developer traffic, simultaneously.

This inverts the project

It is not "12 ms vs 119 ms." It is: the product's detection value lives almost entirely in the layer that costs 100× the SLO, and the layer that fits the SLO has never been measured and does not work.

Consequence for the Tier-1 rewrite

A verdict-identical rewrite is achievable — 0 verdict diffs across 44 _scan_prompt_sync inputs, 1,432 _segment_token tokens, 28 _fuzzy_scan inputs M. It is a 32× win. But byte-identical verdicts is now the wrong goal: it is a gate that faithfully preserves a detector measured at 0/10 paraphrase recall and 5/5 false-positive on inline code.

Tier-1 optionCost @1024 tokVerdicts
Verdict-identical rewrite63.4 ms Mpreserved — including the defects
Change the detectorfloor 0.34–0.54 ms Mdifferent — must be scored against a corpus that does not yet exist

You cannot choose between these without a detection corpus. That is Gate 0.

The instrument is also broken. ttft_ms and duration_ms both derive from provider_start_ts (pipeline_trace.py:120-131); total_latency_ms = duration (:738,:778); the bench computes addon = total − model_output. Therefore addon = TTFT. On streaming requests the benchmark measures the customer's model, not the firewall — so the 12 ms gate passes unconditionally and Phase 1's "stop and revise" gate cannot fire.

3 · The embedding + trained-head alternative — and why it fails

A static embedding with a trained classifier head looked like the escape route: ~500× cheaper than a transformer, with published precedent (NemoGuard-JailbreakDetect, F1 0.9601, is a classifier head over embeddings — not a transformer judge). The devil's advocate trained the head that nobody else had trained.

AUC 0.60, recall 2.8% at the deployed window. The mechanism is dilution, not order-invariance — it works at 21 tokens and collapses at 260. And the arithmetic that kills it outright: 51 windows × 1% per-window FPR = 40% per-request FPR.

Cost was never this design's problem (~1.5–2 ms at the band). The multiple-comparisons FPR budget is. A cost-only gate admitted it; a quality gate excludes it. This is why L2 must name a model class with a GFLOP-per-window entry gate and a published recall floor, evaluated at the deployed window size with a per-request FPR budget.

The lever that was never evaluated

GPU was rejected using an AWS price in a GCP-locked plan. NF — no GCP accelerator rate appears anywhere in the bill of materials. GCP asia-south1 has nvidia-l4 in zones a/b/c with on-demand quota 8, and g2-standard-4 machine types. This is the only lever that closes the classifier gap outright, and it has never been priced on the correct list.

6 · Cost — egress dominates, compute does not

Egress plus load-balancer data processing is 94.6% of the best realistic case at 100k RPS. Compute is 5.1%.

The reframe. Making the code faster buys nothing. Making it emit fewer bytes buys 11.6×. Both are code changes — but they are different code, and only one of them was in the old plan.

The highest-return single fix

The terminal SSE frame carries the full pipeline_trace: 41,424 bytes, with 21 copies of the prompt and 7 of the response, on every allowed request, streamed and non-streamed, with no config flag. _scrub_trace_for_client (main.py:723) is called from exactly one place — :955, the blocked path. This is 24% of the entire $5k budget today.

The architectural unlock

G2 bundles the GPU and the vCPUs in one VM M — confirmed three ways. So the classifier runs in-process with zero network hop. Every alternative topology starts at ≥16.1 ms RTT, which is exactly the hop tax MASTER D1 said a 12 ms budget cannot absorb. The GPU decision does not pay that tax — it dissolves it.

4 × g2-standard-24 in asia-south1, zones a/b/c, 3-year CUD — 96 vCPU + 8 × NVIDIA L4.

The runtime is not a tuning knob. ORT 1.29.0's MODEL_TYPES has no deberta, and fusion is a graph-level pass applied before execution-provider assignment M — so the ORT CUDA EP would run the same unfused graph on the GPU. Native TensorRT is mandatory, served by Triton with both GPUs behind one shared queue (worth 8 ms of p99 versus 8 single-GPU nodes, at identical price).

I2 · No per-request FPR — the biggest finding

The design quotes PG2-22M's 88.7% recall @ 1% FPR V. That operating point is per 512-token window, and Meta's own model card prescribes an OR over segments. So per-request FPR = 1 − 0.99W:

windowsper-request FPRfalse ENFORCE-blocks/s @1,064 RPS
11.00%10.6

This is structurally the same error that correctly killed the potion-8M design (51 windows × 1% = 40% per-request FPR). Applied to its own recommendation it survives only because W is small — and it was not stated at all. In an ENFORCE posture, 2% is a product-defining number.

Two further omissions: the model card publishes multilingual AUC 0.942 against 0.995 English — the operative figure for a Mumbai deployment — with no multilingual recall@1%FPR published NF; and the 88.7% is on Meta's private benchmark, against an 8–16 point AUC collapse under leave-one-dataset-out in our own citations.

I3 · The band must be stated in tokens

Measured chars/token is 3.04 (markdown) / 6.28 (prose) M — never the 4.00 rule of thumb. 1,024 tokens is 3,158 characters of this corpus, not 4,096. And the deployed cap is 10,000 characters (scanner.py:74) — so the 6 ms figure describes a sub-band of the deployed configuration, presented as the configuration.

The one sentence that can be said to a customer

"A full deterministic scan plus a 22M-parameter transformer injection verdict on every request — synchronously and block-capable before any byte reaches the provider — at a projected 4–6 ms p50 / ~18 ms p99 of added latency for prompts up to 1,024 tokens, and 590–1,064 RPS on a single-region $5,000/month footprint; every GPU figure is derived from NVIDIA's published TensorRT measurements of this exact architecture and none is yet measured on our own hardware. We cannot yet quote a false-positive rate: the classifier's published 1% FPR is per 512-token window, which compounds to ~2% per request at two windows and ~7% at our deployed 10,000-character cap."

Everything before the semicolon is strong. Everything after it is why this is not yet a product claim. A defensible 10 ms with a published per-request FPR beats an indefensible 6 ms with none.

The three actions, reordered by what the audit changed

  1. Measure the production prompt-length distribution in tokens. One day of telemetry. It sets the window count — which sets the latency headline, the RPS headline and the per-request FPR simultaneously. Cheapest high-value action in the workstream.
  2. Run the trtexec bake-off — $7, 30 minutes — sweeping --optShapes at W = 1, 2, 3, 4, 7. It must settle: is window-batch-1 inside 2.7–4.0 ms; where throughput saturates (the 490 vs 1,580 windows/s spread is 3.2× and directly sets $/RPS); p95/p99 over 1,000+ iterations — no tail data exists anywhere, and a 72 W card under sustained load is exactly where tails appear; and whether DeBERTa INT8 works on TensorRT at all NF, currently a coin-flip worth 2× throughput.
  3. Publish a per-request FPR budget before the demotion ships, scored at the deployed window count and including multilingual.

13 · What we must not claim

The list exists because several of these were about to be claimed.

Latency

  1. No "12 ms" without a posture, a prompt band, and a percentile. Today's honest sentence: "≈119 ms p50 with semantic classification on; a Tier-1-only posture is projected at 3–5 ms p50 once rewritten, with p99 unmeasured."
  2. No streaming latency number from the current bench. It measures the customer's model.
  3. No p99 for any posture. The 40 ms clause is unbacked.
  4. No figure "on c4a / Axion." Nothing was measured there.
  5. Not N ≈ 85 RPS/host — a 32–64-token number; at 1024 tokens it is ~5.
  6. Not 100k RPS.

Detection

  1. We cannot claim the default posture detects prompt injection. 3/10 same-family, 0/10 paraphrased.
  2. We cannot claim a low false-positive rate. 5/5 benign inline-code prompts and 3/12 ordinary tool descriptions hard-blocked at confidence 1.00, terminally.
  3. No tool/function-calling support at the 1024-token band — ~6–7 ordinary tools tip the request into block/dos/context_length_exceeded.
  4. No supported prompt length above ~1,970 tokens — ~800 in Hindi, ~750 in Tamil, in an India-only deployment.
  5. Streaming "block" is not a block.
  6. Responses are not Tier-2 scanned end-to-end — and telemetry attests that they are.
  7. No per-tenant policy isolation.
  8. Policy enforcement is not fail-closed.
  9. No bounded revocation or config-propagation time. auth:epoch does not exist.
  10. No complete enforcement records.
  11. Tier-2 does not see the whole response — _head_tail silently drops the middle of any answer over 10,000 characters.
  12. No availability during cache maintenance under the kill-switch contract as signed.

Process

  1. Do not present target values as measurements. The "2.39 ms" row is a sum of unbuilt targets, two of which the same document calls unreachable.
  2. potion-base-8M is not a viable Tier-2 replacement. AUC 0.60 / 2.8% recall at the deployed window.
  3. The off-host option was not evaluated. It was rejected on a price from a different cloud.

For the person who signs this

The 12 ms lock cannot be met with a semantic classifier on this hardware inside this budget, and no priced path to it exists. That part survived five adversarial reviews and a devil's advocate.

But the recommendation built on top of it is not safe to ship. It proposes defaulting to the deterministic layer and certifying 12 ms for that default — and nobody measured what the deterministic layer detects until this review: 0 of 10 paraphrased prompt injections caught, 5 of 5 benign questions containing inline code hard-blocked.

The plan spent seven agents optimising the latency of a control whose effectiveness had never been measured, and was about to publish an SLO for it. Fix the instrument, measure the detection, price the GPU, then choose the posture — in that order. The engineering work is real and ~10× is available this quarter with no new dependencies. But the decision in front of you is a product decision about what this firewall actually stops, and it cannot be made from a latency table.
