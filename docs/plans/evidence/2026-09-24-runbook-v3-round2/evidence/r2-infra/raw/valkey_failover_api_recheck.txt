RE-CHECK: "Memorystore for Valkey has no manual failover" (controller task FP7, reviewer-false-positives §7)
Written 2026-09-24 ~12:50Z by r2-infra. Project ai-mesh-firewall, asia-south1. No token is printed anywhere.
Raw artefacts: raw/failover_recheck/

VERDICT: CONFIRMED, now on valid evidence. The earlier evidence files were invalid, as the reviewer said.
  The Memorystore (Valkey) API has NO failover, switchover or promote RPC on projects.locations.instances in
  v1, v1beta or v1alpha. gcloud has no such verb in GA, beta or alpha. The Valkey FAILOVER command is on
  Google's documented blocked list and returns NOPERM. The only operator-triggered role change remains
  `gcloud memorystore instances update <id> --location=<region> --simulate-maintenance-event`.

WHY THE OLD EVIDENCE WAS INVALID (reviewer correct)
  - raw/valkey_acl_probe.txt: every line is NOPERM 'acl|dryrun' because ACL DRYRUN ITSELF is blocked.
    Google's "Blocked commands" list includes "ACL | DRYRUN" (raw/failover_recheck/doc_supported-commands.txt).
    That file therefore says nothing about FAILOVER or any other command.
  - raw/memorystore_v1{,beta,alpha}_discovery.json are 403 error bodies, not API listings.
  - The claim was actually based on the gcloud-bundled generated clients and a direct command probe. Neither
    was saved as a separate file. Both are recorded below.

      Control: the same bearer token lists instances fine (HTTP 200: rv-r2-state-kv, rv-r2-valkey, rv-r2-chaos-kv;
      list_instances.json).
  1b. METHOD-EXISTENCE PROBE against a NON-EXISTENT instance (rv-r2-nonexistent-kv), so no real instance could be

  1c. gcloud-bundled generated clients (raw/failover_recheck/sdk_generated_client_methods.txt). These are

      Failover-like: NONE. For comparison, the redis v1 client has redis.projects.locations.instances.failover.

(2) gcloud verbs (raw/failover_recheck/gcloud_memorystore_instances_verbs.txt; Google Cloud SDK 586.0.0).
    GA, beta and alpha all list the same verbs:
      backup create create-token-auth-user delete describe finish-migration get-certificate-authority
      get-shared-regional-certificate-authority list reschedule-maintenance start-migration update
    There is no failover verb. The only role-change lever is `update --simulate-maintenance-event`. Google's docs
    describe it as "performing planned failovers on all nodes within the instance"
    (raw/failover_recheck/doc_simulate-maintenance.txt).
